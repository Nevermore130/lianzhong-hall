# 本地验收

自动化命令：`npm run build && npm test`。测试服务使用内存数据库或临时目录，不连接开发服务器。

## 已做浏览器检查

- 桌面宽屏：整屏青蓝工具栏、无卡片的棋桌大厅、右侧房间树和玩家表格正常呈现。
- 390px 手机：棋盘与房间可操作，没有页面横向溢出。
- 单机练习：中心落子后电脑回棋，之后轮回到玩家。
- 实时房间：游客入座、准备，刷新后同一身份和准备状态保留。
- 开发 HTTP / WebSocket 代理可以完成身份启动和快照同步。

## 手动回归步骤

1. 普通窗口和无痕窗口各进入一次，两种身份显示为两位在线玩家。
2. A 创建房间，复制链接到 B；分别选择黑白席位并准备。
3. 交替落子，检查两个窗口棋盘同步；空闲第三个窗口可观战。
4. 断开 A，B 暂停落子；30 秒内恢复则继续，否则 A 负、B 胜。
5. 双方准备再开一局；旧棋谱不能继续落子，认输后只结算一次。
6. 注册/登录并完成对局，重启服务后账号与胜负仍在；棋局与聊天清空。
7. 搜索房名/编号、清空搜索、收藏/取消收藏、隐藏满桌、清空搜索，检查空状态。
8. 窄屏点击游戏目录、打开帮助/登录、用 Tab 和 Escape 操作弹窗。

同浏览器多个普通标签页共用 Cookie，被当作一个玩家。这是刻意设计，不是在线人数丢失。
