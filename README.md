# 联众风格游戏大厅

参考用户提供的经典联众客户端截图实现：Windows 98 灰色工具栏、蓝灰游戏桌大厅、右侧房间树与玩家表格、底部聊天区。整屏客户端布局，无欢迎海报或宣传卡片。与联众官方无关联。

这是可以继续开发的全栈版本：**账号 + 实时大厅 + 双人五子棋 + 中国象棋 + 三人斗地主 + 四人中国麻将** 已贯通。

**生产部署**：参见 [部署指南 (docs/DEPLOY.md)](docs/DEPLOY.md)，基于香港 VPS + Caddy + systemd 的真实部署经验编写。

## 运行

需要 Node.js 24+（本机验证版本 25.9.0）。

```sh
cd /Users/jettzhang/code/lianzhong-hall
npm install
npm run dev
```

打开 [游戏大厅](http://127.0.0.1:5188)。前端 5188，服务端 3088；前端代理 `/api` 与 `/ws`，保留原 Host 做同源校验。

本机生产构建验证：

```sh
npm run build
npm start
```

打开 [构建版本](http://127.0.0.1:3088)。`npm start` 同时提供构建后的静态文件、HTTP API、WebSocket。

## 玩一局

1. 自动以游客进入，也可注册昵称和密码，或登录已有账号。
2. 点击五子棋棋桌，选择黑棋或白棋席位。
3. 点击“邀请好友”复制房间链接，使用另一种浏览器或无痕窗口打开。
4. 第二个玩家入座，双方点击准备，黑棋先行。
5. 自由五子棋，横、竖、斜连续五子或更多即获胜，不设禁手。

同一浏览器的标签页共用账号，不能作为两个不同棋手。没有对手时可点“单机练习”，与电脑对弈，不记战绩。当前地址只在本机有效；跨设备使用需另行配置可访问的部署地址。

## 玩中国象棋

1. 选择“中国象棋”，进入六张默认棋桌之一，或创建象棋房间。
2. 两个独立身份分别执红、执黑，双方准备后红方先行；其他人可旁观与使用房间聊天。
3. 点击自己的棋子，再点绿点走棋，绿圈表示可吃子；将军时必须应将。棋谱、吃子记录、末步与将军标记随棋局更新，支持翻转棋盘。
4. 支持求和、认输与再来一局；断线暂停，30 秒内重连恢复，超时判负。胜负摘要落库，和棋不增加胜负数。
5. 选择象棋后点击工具栏“单机游戏”即可练习，可选红黑、入门/普通电脑、提示和悔棋一回合。电脑在 Web Worker 中计算，单机不计战绩。

基本行棋依据 [世界象棋联合会规则](https://www.wxf-xiangqi.org/images/wxf-rules/2018_World_XiangQi_Rules_English2018.pdf)：支持蹩马腿、塞象眼、过河限制、九宫、炮架、兵卒过河和将帅照面；将死及困毙均判负。本版采用明确的娱乐和棋规则：同一局面三次重复，单方持续长将判该方负，其余判和；连续 120 步未吃子判和。复杂长捉、赛事棋例裁定及比赛计时尚未实现。

新素材在 [中国象棋资源清单](public/assets/xiangqi-v1/manifest.json)，两张内置 imagegen PNG 母版及提示词在 [素材源目录](assets/source/xiangqi-v1/PROMPTS.md)。旧木棋盘与透明木棋子使用 WebP，精确格线和 14 种红黑字层使用 SVG；两方复用圆形底层并等比缩放。`node scripts/build-xiangqi-assets.mjs` 可重建 SVG、清单与 [素材预览](http://127.0.0.1:5188/assets/xiangqi-v1/preview.html)。

## 玩斗地主

1. 切换到“斗地主”，选择六张默认桌之一，或创建斗地主房间。
2. 三个独立身份入座并全部准备后发牌；同一浏览器的普通标签页仍视为一个人。
3. 轮流选择不叫、1 分、2 分或 3 分，只能加叫；3 分立即确定地主，全部不叫则重新洗牌。地主获得三张底牌并先出。
4. 点击手牌选中，再点“出牌”；“提示”轮换可出的组合，“重选”清空选择。接牌可不出，连续两家不出后由上一家重新领出。
5. 地主先出完为地主胜，任一农民先出完为两位农民共同获胜。结算后重新准备可再来一局。

只想体验时，选中斗地主再点击工具栏“单机游戏”，由两位本地电脑陪练，不记账号战绩。电脑使用基础合法出牌策略，尚未做高水平牌力分析。

采用经典叫分规则，基础流程参考 [JJ 官方斗地主规则](https://www.jj.cn/djddz/)。支持单张、对子、三张、三带一/对、顺子、连对、飞机及带翅膀、四带二/两对、炸弹、王炸；顺子不能包含 2 或王。本版本飞机单翅可含对子，但不能带主体点数、三张同点或双王；四带二可带对子但不带双王。炸弹、王炸和春天各翻倍，反春天为地主只出过一手。底分乘倍数为单位，地主胜负计 ±2 单位、两名农民各计 ∓1 单位；仅记录本局娱乐分，没有货币、筹码余额或支付。

发牌由服务端随机洗牌，各玩家只收到自己的手牌；叫分结束前不公开底牌，旁观者始终没有玩家手牌。断线保留 30 秒并暂停操作，超时按离开处理：叫分时取消且不计战绩，出牌后判离开者所在阵营负，农民退出会影响队友。

## 玩中国麻将

1. 切换“中国麻将”，进入六张默认麻将桌之一，或创建自己的四人房间。
2. 四个独立身份选择东、南、西、北席位，全部准备后发牌；东位坐庄，14 张先出，另外三家各 13 张。
3. 点击手牌后点“出牌”，也可用“提示”选出建议弃牌。可吃、碰、杠、胡时操作区会出现相应按钮；不需要时点“过”。多种吃法会分别列出。
4. 三家手牌与暗杠内容保密；可展开牌河查看按时间排列的弃牌，副露显示在对应玩家旁。结算后四家亮牌，再次准备可开新局。
5. 选择麻将后点击“单机游戏”，可由三位电脑陪练，不计账号战绩。电脑仅使用本人手牌和公开信息，采用基础组合启发式策略。

**本版大众简化规则**：136 张无花牌；支持平胡（四组顺子或刻子加一对）、门清七对、十三幺；七对允许四张相同牌计作两对。仅下家可吃；胡 > 碰／杠 > 吃，同级按距出牌者近者优先，一炮一响。等待所有具备操作资格的玩家回应后统一裁定，不按网络先后抢操作。支持明杠、暗杠、补杠，补杠可抢胡，杠后从牌墙尾补牌；摸牌后才可自摸、暗杠或补杠。牌墙用尽前仍可胡最后一张弃牌，否则流局；无可补牌时不可杠。无花牌、起胡番数、番种加成、连庄和风圈，未实现完整国标赛事计分。

自摸者 +3，其他三家各 −1；点炮或抢杠胡者 +1，放铳者 −1，其余两家 0；流局全员 0。杠不另计分，无余额。胡牌者账号胜局 +1，负分者负局 +1，未涉及者不计胜负。中途退出或断线超过 30 秒则中止本局，只给退出者记负，其他人不计胜负，四人得分均为 0。断线期间暂停操作，30 秒内重连恢复原席位与手牌。

素材包含原创旧象牙牌面、绿毡桌布、四人木桌椅与 34 种 SVG 牌字，前后层始终按 2:3 比例组合。手机手牌为 34×51px，独立横向滑动，提示会滚动到所选牌。PNG 母版及提示词在 [麻将素材源目录](assets/source/mahjong-v1/PROMPTS.md)，WebP、SVG、共享牌面 CSS 和 [资源清单](public/assets/mahjong-v1/manifest.json) 在 `public/assets/mahjong-v1/`。运行 `node scripts/build-mahjong-assets.mjs` 可重建牌字、清单和 [整套素材预览](http://127.0.0.1:5188/assets/mahjong-v1/preview.html)。

## 数据与边界

SQLite 默认写在 `data/hall.sqlite`，包含账号、会话、四款游戏的结果摘要、聊天记录与已读位置。象棋和五子棋结果通过 `results.game` 区分；斗地主的阵营、底分、倍数、春天与三人得分一起落库。麻将结果在 `mahjong_results` 与 `mahjong_result_players`，保存结束类型、胡牌／放铳席位、四人胜负及分数；注销会将对应玩家引用置空。玩家列表的胜负是四款游戏的合计。服务重启不会丢失这些记录；**自建房间、系统广播、棋谱/出牌记录和进行中的对局仅在内存中，重启会清空**。默认桌重新创建并沿用原频道编号。旧数据库启动时增量增加字段和表，保留既有账号、战绩、会话和聊天。

这是单进程开发版。尚未实现手机绑定、第三方登录、二步验证、自定义头像上传、每步计时、联机托管、完整对局记录持久化、服务重启恢复、多节点部署、排行榜和好友系统。在线数量与聊天均为真实数据；电脑仅出现在单机练习中。

## 聊天使用

默认进入大厅频道，进桌后自动切换到“房间聊天”，可以切回大厅；旁观者也属于房间成员。离房后不再接收或读取该房间聊天。两种频道各自保存草稿和未读数。

“已发送”表示服务端已将消息写入 SQLite，不代表对方已读。发送失败或 8 秒未收到确认时保留原文，可点击重试、编辑或移除；重试沿用原编号，不会重复写入。没有自动批量重发，避免离线积压突然刷屏。其他频道的待发消息可从“待发”按钮管理，重试房间消息需要重新进入原房间。

向上翻阅时不抢滚动位置；新消息显示未读数，点击提示返回最新消息。窗口可见、没有弹窗遮挡且当前频道位于底部时，更新服务端已读位置。首次进入一个频道只把后续消息算作未读，旧记录仍可查看。

默认棋桌的频道编号固定，重启后仍可查看该桌历史；自建房间尚未恢复持久化，重启后其历史保留在数据库中，但房间入口不恢复。自建房间编号持久递增，避免新房间误用旧房间的聊天记录。此前仅在内存中的旧版聊天不具备可迁移的历史副本。

## 账号与邮件验收

进入工具栏“我的账号”，可在 Windows 98 属性窗口中管理资料、密码/邮箱、设备及注销。游客点击“注册账号”直接转正；登录已有账号则切换到该账号，不合并两份战绩。

开发环境默认启动 [本地邮件收件箱](http://127.0.0.1:3089/)。绑定邮箱或找回密码后打开收件箱，再点击邮件内链接完成操作。邮件只保存在本机内存中，不对外发送，服务重启会清空；本地收件箱没有独立密码，仅适用于可信的本机开发环境。

真实邮件使用 SMTP：复制 `.env.example` 为 `.env`，配置 `MAIL_MODE=smtp`、`SMTP_HOST`、`SMTP_PORT`、`SMTP_FROM`、所需认证信息和 HTTPS 的 `APP_ORIGIN`。465 端口使用 TLS，其他端口强制 STARTTLS。`NODE_ENV=production` 默认禁用邮件，禁止开启本地收件箱；未配置邮件服务时，页面明确提示暂不可用。

修改密码保留新建的当前会话、退出其他设备；验证/更换邮箱及忘记密码重置会撤销全部会话，用户须重新登录。邮箱仅在本人的账号中心可见，不进入在线玩家列表或聊天快照。

## 环境变量

| 变量                                | 默认值                         | 用途                                                  |
| ----------------------------------- | ------------------------------ | ----------------------------------------------------- |
| `PORT`                              | `3088`                         | HTTP 与 WebSocket 监听端口                            |
| `HOST`                              | `127.0.0.1`                    | 监听地址                                              |
| `DATABASE_PATH`                     | `data/hall.sqlite`             | SQLite 文件                                           |
| `APP_ORIGIN`                        | 根据请求 Host 做同源检查       | 同源检查及邮件回跳地址，部署时必须设置实际站点 Origin |
| `MAIL_MODE`                         | 开发 `local` / 生产 `disabled` | `local`、`smtp` 或 `disabled`                         |
| `MAIL_INBOX_PORT`                   | `3089`                         | 本地收件箱端口，仅监听 127.0.0.1                      |
| `SMTP_HOST/PORT/FROM/USER/PASSWORD` | 无 / 587 / 无 / 无 / 无        | 正式邮件服务配置                                      |
| `NODE_ENV`                          | 未设置                         | `production` 时会话 Cookie 添加 Secure，需 HTTPS      |

服务端自动加载 `.env`，已有环境变量优先。开发邮件默认回跳 5188，`npm start` 默认回跳后端端口；设置 `APP_ORIGIN` 可覆盖。

前端开发代理默认固定指向 3088；变更服务端开发端口时同步修改 `vite.config.ts`。不要把 Vite 开发服务器当作公网部署服务。
