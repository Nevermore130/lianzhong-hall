# 联众风格游戏大厅

参考用户提供的经典联众客户端截图实现：Windows 98 灰色工具栏、蓝灰游戏桌大厅、右侧房间树与玩家表格、底部聊天区。整屏客户端布局，无欢迎海报或宣传卡片。与联众官方无关联。

这是可以继续开发的全栈第一版：**账号 + 实时大厅 + 双人五子棋** 已贯通。斗地主、麻将和象棋是标注“筹备中”的入口，尚未实现规则。

## 运行

需要 Node.js 24+（本机验证版本 25.9.0）。

```sh
cd /Users/jettzhang/code/lianzhong-hall
npm install
npm run dev
```

打开 [游戏大厅](http://127.0.0.1:5188)。前端 5188，服务端 3088；前端代理 `/api` 与 `/ws`，保留原 Host 做同源校验。

本机生产构建验证：

```sh
npm run build
npm start
```

打开 [构建版本](http://127.0.0.1:3088)。`npm start` 同时提供构建后的静态文件、HTTP API、WebSocket。

## 玩一局

1. 自动以游客进入，也可注册昵称和密码，或登录已有账号。
2. 点击五子棋棋桌，选择黑棋或白棋席位。
3. 点击“邀请好友”复制房间链接，使用另一种浏览器或无痕窗口打开。
4. 第二个玩家入座，双方点击准备，黑棋先行。
5. 自由五子棋，横、竖、斜连续五子或更多即获胜，不设禁手。

同一浏览器的标签页共用账号，不能作为两个不同棋手。没有对手时可点“单机练习”，与电脑对弈，不记战绩。当前地址只在本机有效；跨设备使用需另行配置可访问的部署地址。

## 已实现

- 游客、注册、登录、退出；密码 scrypt 哈希；HttpOnly 会话 Cookie；会话有效期 7 天。
- 真实在线人数、房间创建和搜索、本机收藏、入座/站起/准备、旁观、大厅聊天。
- 服务端判定落子、轮次、胜负；拒绝观众落子、抢座、旧棋局命令和无效位置。
- 同账号多标签页在线状态合并。断线保留座位 30 秒，期间暂停落子，超时判负；刷新可恢复。
- 认输、离开判负、再来一局；注册账号与游客的胜负记录都落盘。
- 桌面分栏和手机布局、键盘焦点、原生弹窗焦点管理、可选落子音效。

## 数据与边界

SQLite 默认写在 `data/hall.sqlite`，包含账号、会话和结果摘要。服务重启不会丢失这些记录；**房间、聊天、棋谱和进行中的对局仅在内存中，重启会清空**。游客升级为注册账号的战绩迁移尚未实现。

这是单进程开发版。未实现密码找回、账号风控、每步计时、完整棋谱持久化、服务重启恢复、多节点部署、排行榜和好友系统。在线数量与聊天均为真实数据，没有模拟机器人撑场。

## 环境变量

| 变量            | 默认值                   | 用途                                             |
| --------------- | ------------------------ | ------------------------------------------------ |
| `PORT`          | `3088`                   | HTTP 与 WebSocket 监听端口                       |
| `HOST`          | `127.0.0.1`              | 监听地址                                         |
| `DATABASE_PATH` | `data/hall.sqlite`       | SQLite 文件                                      |
| `APP_ORIGIN`    | 根据请求 Host 做同源检查 | 反向代理部署时设置实际站点 Origin                |
| `NODE_ENV`      | 未设置                   | `production` 时会话 Cookie 添加 Secure，需 HTTPS |

前端开发代理默认固定指向 3088；变更服务端开发端口时同步修改 `vite.config.ts`。不要把 Vite 开发服务器当作公网部署服务。
